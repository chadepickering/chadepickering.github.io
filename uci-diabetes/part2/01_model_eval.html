4.1 Overview

This document evaluates four classifiers trained to predict 30-day hospital readmission in diabetic patients. The deployment threshold is τ=0.12, selected via a sweep of τ=0.10–0.15 to find the operating point closest to the Part 1 experimental design target of ~15.7% flagged (3pp ARR MDE, O’Brien-Fleming group sequential boundaries). τ=0.10 was explored during model development; those results are retained in the source metrics JSON files for reference.

All models apply post-hoc probability calibration (Platt scaling for LR/XGBoost/ LightGBM; isotonic regression for TF/Keras). Class imbalance (~13:1) is addressed via class_weight='balanced' (LR/LightGBM/TF) or scale_pos_weight=13.04 (XGBoost).

4.3 Threshold Sweep (τ=0.10–0.15)

Threshold-dependent metrics vary substantially across this range due to the concentration of predicted probabilities between 0.10 and 0.15 — a consequence of probability calibration compressing scores toward the positive class base rate. This sweep identifies the operating point closest to the Part 1 design target.

Key observations:

  • All models show a steep flag-rate drop between τ=0.10 and τ=0.15, reflecting concentration of calibrated probabilities in this range.
  • τ=0.12 is the operational sweet spot: XGBoost flags 16.1% (≈15.7% target), LightGBM flags exactly 15.7%, and both reach their peak F1 here.

  • LR undershoots the target at τ=0.12 (12.0% flagged) — the linear model’s probability distribution is more compressed than the tree models.

3. Precision: XGBoost leads tree models on precision@tau (0.124), flagging a

4. Interpretability: SHAP TreeExplainer provides feature-level explanation for each
   prediction -- operationally important for clinical trust and regulatory review.

5. Inference simplicity: Single joblib file, no TF/Keras dependency, no
   two-stage calibrator load pattern.

4.12 Key Findings and Deployment Implications

Modest discriminative performance: Best holdout AUC-ROC ~0.687. The dataset’s 7% positive rate and ~1-week look-back window limit the theoretical ceiling. Performance is consistent with published EHR readmission models.

Linear signal dominates: LR closes to within 1pp of XGBoost on AUC-ROC. The non-linear lift from tree models is real but modest; deployment cost/complexity should be weighed against this marginal gain.

Non-linear utilization signal: total_prior_encounters ranks #45 in LR but #3 in XGBoost SHAP — non-linear utilization effects are real and captured only by tree models.

Causal consistency: All six features with Part 1 directional priors are consistent across model families, supporting that the model captures clinically coherent signal rather than spurious correlations.

Deployment threshold τ=0.12 aligns with Part 1 design: A sweep of τ=0.10–0.15 revealed that τ=0.12 is the operating point where XGBoost flags 16.1% of patients (≈15.7% Part 1 target) and achieves peak F1. τ=0.10 overshoots (26% flagged); τ=0.15 dramatically undershoots (6%). τ=0.12 resolves this and is consistent with the experimental design power calculation.

Fairness monitoring required: Flag rate disparities across race/gender groups should be assessed against positive rate disparities before deployment. Differential flag rates proportional to differential positive rates are expected; disproportionate flag rates require intervention.

4.12.1 Recommended Next Steps

  1. Threshold confirmation: τ=0.12 is the deployment threshold — selected via a τ=0.10–0.15 sweep as the point where XGBoost flags ~16% of patients (≈15.7% Part 1 target) and achieves peak F1. Confirm flag rate against clinical workflow capacity before go-live.

  2. Fairness audit: Complete subgroup analysis with statistical tests for flag rate parity, calibration by race/gender, and error rate parity before clinical deployment.

  3. Temporal monitoring: The 1.5pp positive rate drop from train to validation/ holdout indicates temporal drift. A monitoring pipeline should track positive rate, flag rate, and AUC-ROC quarterly using held-aside recent encounters.

  4. Deployment architecture: XGBoost via joblib.load is the simplest path — single file, sub-millisecond inference, no GPU dependency. The fitted preprocessor.joblib provides the feature transformation contract; both artifacts must be versioned together.

  5. A/B experiment: The Part 1 experimental design (O’Brien-Fleming, 4 analyses, 3pp ARR MDE, 80% power) provides the statistical framework for a prospective RCT evaluation of this model in production.

def threshold_metrics(y_true, probs, tau):
    """Compute threshold-dependent classification metrics at a given tau."""
    mask = probs >= tau
    if mask.sum() == 0:
        return dict(flagged_rate=0.0, precision_tau=0.0, recall_tau=0.0, f1_tau=0.0)
    prec = float(y_true[mask].mean())
    rec  = float(y_true[mask].sum() / y_true.sum())

#| label: threshold-sensitivity
#| fig-cap: "Precision, recall, and F1 as a function of threshold τ (XGBoost, holdout set)."

thresholds = np.linspace(0.02, 0.40, 200)
metrics_at_tau = []

for tau in thresholds:
    mask = holdout_probs >= tau
    if mask.sum() == 0:
        continue
    prec = y_holdout[mask].mean()
    rec  = y_holdout[mask].sum() / y_holdout.sum()
    f1   = 2 * prec * rec / (prec + rec + 1e-9)
    flag = mask.mean()
    metrics_at_tau.append({"tau": tau, "precision": prec, "recall": rec, "f1": f1, "flagged": flag})

## Key Findings and Deployment Implications

**Modest discriminative performance:** Best holdout AUC-ROC ~0.687. The dataset's
7% positive rate and ~1-week look-back window limit the theoretical ceiling.
Performance is consistent with published EHR readmission models.

**Linear signal dominates:** LR closes to within 1pp of XGBoost on AUC-ROC. The
non-linear lift from tree models is real but modest; deployment cost/complexity
should be weighed against this marginal gain.

**Non-linear utilization signal:** `total_prior_encounters` ranks #45 in LR but
#3 in XGBoost SHAP — non-linear utilization effects are real and captured only
by tree models.

**Causal consistency:** All six features with Part 1 directional priors are
consistent across model families, supporting that the model captures clinically
coherent signal rather than spurious correlations.

**Deployment threshold τ=0.12 aligns with Part 1 design:** A sweep of τ=0.10–0.15
revealed that τ=0.12 is the operating point where XGBoost flags 16.1% of patients
(≈15.7% Part 1 target) and achieves peak F1. τ=0.10 overshoots (26% flagged);
τ=0.15 dramatically undershoots (6%). τ=0.12 resolves this and is consistent with
the experimental design power calculation.

**Fairness monitoring required:** Flag rate disparities across race/gender groups
should be assessed against positive rate disparities before deployment.
Differential flag rates proportional to differential positive rates are expected;
disproportionate flag rates require intervention.

### Recommended Next Steps

1. **Threshold confirmation:** τ=0.12 is the deployment threshold — selected via
   a τ=0.10–0.15 sweep as the point where XGBoost flags ~16% of patients (≈15.7%
   Part 1 target) and achieves peak F1. Confirm flag rate against clinical workflow
   capacity before go-live.

2. **Fairness audit:** Complete subgroup analysis with statistical tests for
   flag rate parity, calibration by race/gender, and error rate parity before
   clinical deployment.

3. **Temporal monitoring:** The 1.5pp positive rate drop from train to validation/
   holdout indicates temporal drift. A monitoring pipeline should track positive
   rate, flag rate, and AUC-ROC quarterly using held-aside recent encounters.

4. **Deployment architecture:** XGBoost via `joblib.load` is the simplest path —
   single file, sub-millisecond inference, no GPU dependency. The fitted
   `preprocessor.joblib` provides the feature transformation contract; both
   artifacts must be versioned together.

5. **A/B experiment:** The Part 1 experimental design (O'Brien-Fleming, 4 analyses,
   3pp ARR MDE, 80% power) provides the statistical framework for a prospective
   RCT evaluation of this model in production.
